## 業績層級資料（`src/tools/sales/`，BigQuery `popinpoc1.reporting.nexus_sales_*`）

- **目的**：經銷商／client／IO（委刊單）＋IO 歸屬到平台帳戶的主檔。主要給 audience_center 的 `/ad-performance`（pacplatform.net/ad-performance）之後 JOIN 出 client／經銷商／屬性維度，也給 AM dashboard、走速改版用。設計 `docs/superpowers/specs/2026-10-14-sales-io-hierarchy-design.md`（為何放 BQ §2、表結構 §4、關聯圖 §4.0、歸屬語意 §5、換表流程 §6.8、已知限制 §9）。
- **現況**：只有資料，**沒有管理介面**，`/ad-performance` 也還沒接；比對不完美可接受。不留修改歷史（一張 IO 只存最新值）。
- **每日同步**（設計 `docs/superpowers/specs/2026-10-19-sales-daily-sync-design.md`）：Cloud Scheduler `sales-sync` 每天 06:00 台北 POST `/tools/sales/cron?key=DIAG_KEY`（`&dry=1` 只算不寫、不發 Chat、通知文字放回應裡）。線上直接讀兩份試算表（服務帳號 ADC，`FORMATTED_VALUE`），月表分頁 202605～當月（當月沒資料就略過）。**只增不減**：試算表刪掉的資料 BQ 照留、照算（算不算進業績由 dashboard 的日期區間決定）；**以 IO 為單位保留**——IO 從試算表消失就連同請款期／預算／歸屬整組凍結，IO 還在時子表以試算表當下為準（只刪單一請款期，BQ 也會少那一期）。Google Chat（`NEXUS_CHAT_WEBHOOK`）只在三種情況發：執行失敗、健全性檢查沒過（未寫入）、疑似改寫造成重複 IO。Cloud Logging 摘要 `jsonPayload.marker="sales_sync"`。
- **疑似重複 IO**：改了 IO 鍵的欄位（財務起始日、公司名）或月表列併進財務 IO，舊 IO 會留著、新 IO 也出現。偵測條件＝今天剛消失的 IO 與今天還在的 IO 共用平台帳戶且走期重疊，只在消失當天通知一次。**盲點**：沒有任何歸屬規則的 IO 偵測不到。管理介面上線前，清重複要由 Claude 手動下 SQL（刪 IO 時連同 `io_periods`／`io_allocations`／`io_assignments` 同 `io_id` 的列）。
- **分層**：`sheets.ts`（讀試算表、月表分頁推算）→ `parse.ts`（試算表列）→ `sanity.ts`（寫入前檢查）→ `names.ts`／`build.ts`（名稱比對、組 Seed）→ `rows.ts`（轉 BQ 列、`checkKeys`、換表交易 SQL）→ `merge.ts`（和 BQ 現有列合併、固定 id）→ `dupes.ts`（疑似重複）；I/O 在 `store.ts`（Cloud SQL 帳戶／BQ 讀寫）與 `sheets.ts`；`sync.ts` 串流程，`route.ts`（cron）與 `scripts/sales_seed.mts`（本機）共用。`report.ts` 覆蓋率報告只有 CLI 產。測試 `npx tsx tests/verify_sales.mts`。
- **BQ 不擋資料錯誤**：唯一鍵、外鍵都靠 `checkKeys`；之後誰要直接寫這些表（管理介面）也要自己檢查。**id 固定**（同鍵沿用：主檔＝正規化名稱、IO＝正規化的 `(source, source_ref)`，月表 IO 不看帳戶名段，補帳戶名不會變新 IO），但改了 IO 鍵欄位就會變成新 IO、新 id。寫正式 BQ 必須傳 `writeRowsToBq(..., { allowProd: true })`（cron 非 dry、CLI `--write` 才傳）。
- **本機跑（除錯、看覆蓋率報告）**：本機 ADC 沒有試算表權限 ⇒ 由 Claude 用 Google Sheets MCP 把財務「在線委刊走期表」「客戶資料表(財務填)」與月表 202605～當月匯出成 `poc/sales_seed_input/*.json`（`{"values": [...]}`，**含財務資料，不進 repo**）→ 開 cloud-sql-proxy → `DB_HOST=127.0.0.1 DB_PORT=3307 DB_SSL=off npx tsx scripts/sales_seed.mts`（只算＋產 `poc/sales_seed_report.md`）→ 要寫才加 `--write`（和排程同一套合併，不會清掉保留的資料）→ 關 proxy。
- **改 schema**：`bqEnsureTable` 對已存在的表不改 schema，換表交易的 `INSERT … SELECT` 會因欄位對不上而整段 ROLLBACK（正式表不變）。要加欄位先 `ALTER TABLE … ADD COLUMN`（DDL 不計費）加在正式表最後、`schema.ts` 同步加在最後，再部署；**不要刪表重建**（只增不減的資料會全丟）。
- **帳戶清單**＝`nexus_coverage` 出現過的帳戶＋D／M token 表＋BH `bh_accounts` active（都經 `core/store.ts` 既有函式、唯讀）；`nan` 等無效 ID 略過。帳戶名比對三級（完全相同／去前綴相同 一起收，互相包含 ≥3 字只在前兩級沒有時用），對不到就略過、列在報告。
- **2026-10-16 第一次寫入的已知缺口**（報告 §3，帳戶層已歸屬 D 26.8%／M 49.5%／P 15.9%／R 33.2%）：①「走期外」1,286 萬有 1,273 萬落在 5～8 月——月表 202605～08 多半沒填帳戶名，那幾個月的 IO 沒規則，9～10 月的 IO 有規則但走期不涵蓋前幾月；②新素簡（康佰耀）6 個 `新素簡_瘦身_*` D 帳戶沒掛上（第 1 級剛好對到同名 M860212，第 3 級不啟用）；③上辰只有 2 字、不到第 3 級門檻，12 個 `上辰-子申…` 帳戶沒掛上。使用者決定先照規則寫，之後整理再補（可做法：早期月份沿用同代理商同廣告主後面月份的帳戶名；陸客帳戶寫固定對照）。
