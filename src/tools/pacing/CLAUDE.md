## 走速核心（tool#10，`/tools/pacing`，`src/tools/pacing/`）

- **目的**（2026-09-30 使用者拍板）：AM 在 BH（Budget Hunter，repo `r_bulk_upload`、Cloud Run `cmp-r`）設定「平台帳戶×預算×真實走期」，但 BH 是一個平台帳戶一列、照上傳順序排。這頁改成**一個預算一列**，合計列看所有平台加總的走速，點開看各平台。**BH 一行不改、`budget_hunter` 庫只讀**（使用者：現在還不想動 BH）。
- **分層**：`calc.ts`（純函式：分組／走速／V 換算／設定錯誤／整頁組裝）、`sheet.ts`（純函式：預算表解析與抓漏）、`source.ts`（讀 Google Sheet）、`route.ts`（組資料＋API）、`page.ts`（畫面）。SQL 在 `core/store.ts` 檔尾「tool#10 走速」段。
- **資料來源**：
  - BH 設定：`budget_hunter.bh_accounts`（status=active），同一個 Cloud SQL 跨庫唯讀（env `BH_DB` 可改庫名）。
  - 花費 D/R/M/P：`ad_tools.nexus_coverage`（nexus 每日批次記的帳戶×日加總，**不查 BQ、不花錢**）。資料日＝各平台最大 dt（≤ 昨天）；批次還沒跑完時是前天，剩餘天數從資料日隔天算。
  - 花費 V（D1 影音）：倉庫沒有 ⇒ 讀 BH 的 `bh_daily_stats`（BH 用 Action4 抓好的）。之後 V 收進倉庫再換。
  - 預算表：Sheets API 唯讀（服務帳號 2026-09-30 已加檢視者），讀當月分頁 `YYYYMM`、用表頭名稱找欄、快取 10 分鐘。**只拿來抓漏，不當走速來源**（按月切走期、P 欄是剩餘公式，見 memory budget-deliver-sheet）。
- **預算列＝自動分組＋手動合併**：名稱正規化（NFKC、小寫、去空白與 `_-()` 等）後相同**且起訖日完全相同**的設定併一列（2026-10-01 實測 active 80 筆 → 56 列、跨平台 18 列；同名不同檔期如貸霸 6/9~7/8 與 9/9~10/8 正確分開）。名字不同的靠頁面「合併列」，存 `ad_tools.pacing_merges`（bh_id → group_id；本工具自管表，第一次讀時 CREATE）。合併以「自動群組」為單位做 union：AM 之後再上傳同名同走期的設定會自動跟進合併後那列。
- **計算**（子列與合計列同一套 `judge`）：已花＝走期內到資料日；每日應花＝(預算−已花)÷剩餘天數（含今天，同 BH）；預估結案＝已花＋**近 7 日**平均×剩餘天數（平日週末差很多，3 天會被週末拉低；不滿 7 天用已跑天數）。燈號門檻在 `PACE`：
  - 🔴 開跑 ≥2 天仍 0 花費／進行中已花超過預算／預估結案 <85%（開跑 ≥3 天才判）／已結束結案 <85% 或超支 >5%（`overTol`，9 月回測 23 筆結束紅燈有 6 筆只超 0~5%）
  - 🟡 預估結案 >115%／走期結束後還在花／預算 0 卻有花費
  - **合計列只看總額**：單一平台落後是子列紅燈，總額達標合計就不紅（平台拆分只是參考，使用者定調「以預算為主」）。
- **V ×0.6**：D1 後台「金額」＝客戶價×0.6（實測 D1 金額 CPM 恆為 72、預算表客戶 CPM 120）；AM 在 BH 填的 V 預算也已乘過（juliat 預算 5,400、9/29 花 5,289）。子列照原數字，加進合計列前 ÷0.6 換回客戶價（`toClient`）。
- **BH 設定錯誤標在子列**（`configIssues`）：帳戶 ID 無效（Excel 空白上傳存成 `nan`）、MGID 填成 Client ID（97/98 開頭，要填 86 開頭的 API ID）、token 表與倉庫都沒有的帳戶、同帳戶走期重疊（花費算兩次）。2026-10-01 實測：#260 D 直客_仙桃牌 `nan`、經銷商_初忠_環亞 D/M 各重複一筆。
- **排序**：進行中紅 → 進行中黃 → 已結束但還在花 → 進行中綠 → 未開始 → 已結束紅黃（回顧）→ 已結束綠。結束超過 7 天的不顯示（BH 有 3 月、6 月結束卻仍 active 的設定）。
- **預算表抓漏**（只看「已上線」、排除 Meta 代操；名稱比對＝相同或互相包含，表上名字包含系統名字時系統名字要 ≥3 字）：BH 沒設定（「不用AM」的列不算）／可能沒進系統的帳戶（D/M token 表、倉庫、BH 都找不到；影音列不查）／沒填帳戶名。命名規則統一前會誤判，**只列不通知**。
- **跟 BH 數字對帳**（2026-10-01）：進行中 23 筆子列「每日應花」21 筆與 BH 一致（±1%），2 筆差異都可解釋：#260 `nan`（BH 還用 9/21 前的舊數字）、R 10208 仙桃牌（BH 漏抓 4,009，倉庫有）。
- **本機開發**：本機 ADC 沒有試算表權限 ⇒ 設 `PACING_SHEET_VALUES_FILE` 指向匯出的 JSON（`{ "202610": [[...]] }`，日期轉成序號、跟 `UNFORMATTED_VALUE` 同格式）。截圖 `poc/_shot_pacing*.mts`（poc 被 gitignore）。
- **視覺**（2026-10-01 使用者從 v1 表格／v2 跑道兩版 demo 選 **v1 表格**，v2 已拿掉）：Slot Board 外殼；首頁卡片＋導覽列「走速」。走速條＝灰軌（預算）＋墨（已花，超出預算段紅）＋細直線（時間進度）＋菱形（預估結案，顏色跟燈號）。圖例放在表格正上方（使用者一開始看不懂菱形）。展開的子列＝灰底＋內陰影＋縮排＋樹狀連接線（2026-10-01 從三版 demo 選「兩者都有」）。**預設篩選**：只有預算表「負責AM」欄上的人、且有顯示中的列才預設看自己（`defaultAm`），其他人（例：benson 名下只有 3 月的舊設定）預設全部；篩選按鈕只放顯示中的列的負責人。第二版：Chat 通知（每天早上依 AM 分段）、V 收進倉庫。
- 驗證：`tests/verify_pacing.mts`（22 項，全假資料手算期望值）；做過 20 個變異測試全部被抓到（V 不換算、走期前花費算進去、平均視窗改 3 天、未開始剩餘天數多算、0 花費門檻、minDays、超支疊判超前、走期後花費不提醒、分組不看走期、合併沒作用、不重疊也算重複、今天的數字也算、早已結束的也顯示、合計剩餘天數取錯、日期序號差一天、不用AM、影音查 token、名稱對到的 ID 不比對 BH、Meta 沒排除、短名字到處命中）。
